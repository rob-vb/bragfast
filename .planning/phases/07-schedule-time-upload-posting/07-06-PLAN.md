<objective>
Close Phase 7 verification gaps by hardening the schedule-time backend boundary: the public schedule action must be callable only with trusted server proof, the route must prove key/public URL correspondence by deriving URLs from authenticated R2 keys, and Buffer side effects must be durably recorded before any later failure can orphan or duplicate posts.
</objective>

<gap_sources>
- `07-VERIFICATION.md` failed truth 10: `convex/schedulePush.ts` is public and trusts caller-supplied `userId`.
- `07-VERIFICATION.md` failed truth 11: Buffer posts happen before any release row exists, so a later push failure can orphan earlier provider posts.
- `07-VERIFICATION.md` failed truth 12: `src/app/api/v1/schedule/route.ts` accepts caller-supplied `urls` independently from the R2 keys it asks Convex to HEAD-check.
- `07-REVIEW.md` CR-01, CR-02, and WR-01 confirm the same risks.
</gap_sources>

<context_decision_coverage>
This gap-closure plan intentionally leaves the already-executed UI, CLI, Buffer primitive, routing-defaults, and Admin badge behavior intact while fixing the backend invariants that caused verification failure.

- D-01, D-02, D-03: preserved and strengthened by deriving public URLs from authenticated R2 keys, keeping direct CLI R2 upload, and keeping Buffer credentials backend-only.
- D-04, D-05, D-06, D-07: preserved by leaving `pushToBuffer` queue/custom scheduling and image-only validation in place.
- D-08, D-09: preserved by keeping the existing per-format `selections` shape and routing-defaults behavior unchanged.
- D-10, D-11, D-12: preserved and strengthened by turning scheduled release creation into a pending -> scheduled/failed lifecycle that still drives the Admin badge and Workspace confirmation/error copy.
</context_decision_coverage>
