  <action>
    Create `convex/schedulePush.ts` with `"use node"`. Expose a trusted public `action` wrapper named `run` because Next.js route handlers use `ConvexHttpClient` after authenticating. Its args must include `userId`, `draftId`, `urls: Record<string,string>`, `keys: Record<string,string>`, `selections: Array<{format:"landscape"|"square"|"portrait", provider:"buffer", channelId:string, channelName?:string}>`, `caption`, and `scheduling: { type:"queue" } | { type:"custom", scheduledAt:string }`.
    Implementation order:
    1. HEAD-check every `keys[format]` with `headObject`; if any missing, return `{ ok:false, error:"upload_missing", missing:[...] }`.
    2. Fetch sealed Buffer credential via existing internal secret query (`internal.integrationSecrets.getSealedForScan` or equivalent).
    3. `open()` the credential and call `pushToBuffer()` once per selection using matching `urls[selection.format]`, `postState:"queue"`, and the scheduling object from args.
    4. Insert one scheduled release with `externalId` prefix `rel_`, `template:"local-render"`, `credits_used:0`, `images` containing the public URLs, `socialCopy` JSON containing at least `{ caption }`, and metadata JSON containing selected channels, provider post IDs, scheduling type, and `draftId`.
    5. Return `{ ok:true, releaseId, scheduled:[{format, channelId, channelName, providerPostId, scheduledAt?}] }`.
    Do not write `draftPushes` rows.
  </action>
  <acceptance_criteria>
    - `convex/schedulePush.ts` contains `headObject`, `pushToBuffer`, and `insertScheduled`
    - `convex/schedulePush.ts` does not import or write `draftPushes`
    - `npx vitest run convex/__tests__/schedulePush.test.ts` passes
  </acceptance_criteria>
