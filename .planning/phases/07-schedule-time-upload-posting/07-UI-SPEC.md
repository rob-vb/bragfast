Design decisions apply to the correct surface. Rules below call out which surface each applies to.

## Component Inventory

### New: `SchedulePanel` (Workspace SPA)

Location: `packages/workspace/src/components/SchedulePanel.tsx`

**Layout:** Matches the existing `RenderPanel` card pattern — `rounded-[8px] border border-[var(--workspace-border)] bg-[var(--workspace-bg)] p-4`.

**Sections in order:**
1. **Panel heading** — "Schedule post" (16px semibold, `--workspace-forest`)
2. **Channel groups** — one group per available format (Landscape / Square / Portrait), only shown if format has channels available. Each group:
   - Group label: format name (12px semibold, `--workspace-forest`)
   - Channel rows: one per channel. Row = `min-h-[44px]` with a checkbox + channel display name + service icon (Lucide). Pre-checked from `routingDefaults`; seeded from `BUILT_IN_FORMAT_DEFAULTS` if no saved defaults.
3. **Timing toggle** — two radio-style buttons: "Next queue slot" (default, pre-selected) | "Exact time". Toggle uses `--workspace-surface` background, `--workspace-border` border, `--workspace-lime` indicator for selected state.
4. **Date/time input** — visible only when "Exact time" is selected. Native `<input type="datetime-local">`. Styled: `min-h-[44px] w-full rounded-[8px] border border-[var(--workspace-border)] bg-[var(--workspace-surface)] px-3 text-[12px] text-[var(--workspace-ink)]`. Value is converted to UTC ISO-8601 before submission (`new Date(value).toISOString()`).
5. **Buffer not connected notice** — shown when no Buffer integration is found. Copy: "Buffer not connected. Go to brag.fast Settings to connect." (12px, `--workspace-muted`). No submit button shown.
6. **Submit button** — "Schedule post" — full width, `min-h-[44px]`, `bg-[var(--workspace-lime)]`, disabled during upload and scheduling phases.
7. **Progress states** — shown in place of the submit button during upload/scheduling:
   - Uploading: spinner + "Uploading to R2…"
   - Scheduling: spinner + "Scheduling via Buffer…"
8. **Confirmation banner** — shown on success (replaces progress state, persists until panel is dismissed or a new schedule is initiated). See Copywriting section.
9. **Error state** — shown inline below submit button on failure. See Copywriting section.

**Interaction states:**
- Checkboxes: `accent-[var(--workspace-forest)]` (browser default, no custom styling needed)
- Submit button: `hover:opacity-90`, `disabled:cursor-not-allowed disabled:opacity-50` — matches `RenderPanel.tsx` button pattern exactly
- Focus: `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[var(--workspace-lime)]` — matches existing workspace pattern

## Implementation Notes for Executor

1. **Workspace panel placement:** `SchedulePanel` renders inside or adjacent to `Editor.tsx` (same sidebar column as `RenderPanel`). It is shown only when `output === "image"` and `renderPhase === "done"` (i.e., images exist to schedule). Hiding it until render is done avoids scheduling before files exist.

2. **Date/time input UTC conversion:** Always convert `datetime-local` value with `new Date(value).toISOString()` before sending. Display the local-time interpretation back in the confirmation copy, not the raw UTC string.

3. **Channel seeding order:** (1) Load `routingDefaults` per format. (2) For any format with no saved defaults, auto-check channels matching `BUILT_IN_FORMAT_DEFAULTS[format]` by `channelClassFromBufferService`. Never auto-check channels for formats that have saved defaults (respect user's prior choices).

4. **Save-back on schedule:** After a successful schedule, fire one `PUT /api/v1/routing-defaults` per scheduled format (not one combined request — the route processes one format at a time).

5. **No animations beyond existing patterns:** Use only `animate-spin` (for spinners) and `animate-pulse` (for skeletons) — both already exist in the Workspace.
