# Plan 02-03 — `/device` Approval Page

## Objective

Add the browser approval page used by the device-flow login.

## Tasks

1. Create `src/app/device/page.tsx`.
2. Gate with `getSessionUser()`; redirect to `/login?next=/device?code=...` when unauthenticated.
3. Fetch safe code state with `api.deviceCodes.getByUserCode`.
4. Render identity, code, and Approve/Deny controls in the existing PixelCard style.
5. Add `src/components/device/device-approval.tsx` as a client component for mutations.

## Acceptance

- `/device?code=XXXX-1234` never displays `device_code`.
- Approval changes the code state so CLI polling can exchange it.
- Denial changes the code state so CLI polling gets `access_denied`.
