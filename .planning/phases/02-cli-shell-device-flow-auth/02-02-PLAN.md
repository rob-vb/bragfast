# Plan 02-02 — Device API Routes

## Objective

Expose the CLI polling API over Next `/api/v1`.

## Tasks

1. Create `POST /api/v1/device/code`.
2. Create `POST /api/v1/device/token`.
3. Use `fetchMutation(api.deviceCodes.*)`; do not call `authenticate()`.
4. Validate bad JSON and missing `device_code`.
5. Add route tests if the repo’s route-test pattern is straightforward; otherwise rely on the Convex lifecycle tests plus CLI proof script.

## Acceptance

- `POST /api/v1/device/code` returns `{ device_code, user_code, verification_uri, expires_in, interval }`.
- `POST /api/v1/device/token` returns `{ error: "authorization_pending" }` before approval.
- Successful exchange returns `{ access_token, token_type: "Bearer" }`.
