## Spacing Scale

| Token | Value | Usage |

## Color

The Workspace uses `--workspace-*` CSS variables. This phase reuses them exactly — no new tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F6F2` (`--workspace-bg`) | Page background, render panel background |
| Secondary (30%) | `#FFFFFF` (`--workspace-surface`) | Toggle active segment, action button backgrounds |
| Accent (10%) | `#87FF5C` (`--workspace-lime`) | Render button bg, active tab underline, success dot, focus outline |
| Forest text | `#1F3D3A` (`--workspace-forest`) | Primary labels, headings, button text |
| Ink | `#1A1A1A` (`--workspace-ink`) | Rendering-state text |
| Muted | `rgba(26,26,26,0.62)` (`--workspace-muted`) | Idle format label, toggle inactive text |
| Border | `rgba(26,26,26,0.12)` (`--workspace-border`) | Panel border, toggle border, row dividers |
| Destructive | `red-500 / red-600` (Tailwind) | Error state text and badge background |

Accent (`--workspace-lime`) reserved for: Render button background, active tab/toggle underline indicator, success status dot, focus-visible outline. Nowhere else.

Source: `packages/workspace/src/index.css`, `packages/workspace/src/components/RenderPanel.tsx`, `packages/workspace/src/components/FormatSwitcher.tsx`

New sub-elements added to `RenderPanel` for Phase 6 (not separate components):

| Element | Description |
|---------|-------------|
| Output toggle | Inline `image \| video` toggle — two-segment tab control, same visual pattern as `FormatSwitcher` but with two options: "Image" and "Video". Persists to `DraftConfig.output`. |
| Chrome-download gate | Conditionally replaces the Render button when `renderPhase === "chrome-download"`. Shows heading + description + a progress bar. Auto-proceeds; no user action required. |
| Frame progress row | Single row below the Chrome-download gate (or in place of format rows during video render): shows "Rendering video…" spinner + "NNN / 240 frames" counter in Geist Mono. |
| Video preview | `<video>` element (muted, controls, loop=false) replacing the `<img>` preview when `output === "video"` and render is done. |

## Interaction States

All states follow Phase 5 patterns extended for video:

| State | Visual |
|-------|--------|
| `idle` — output toggle image | Toggle shows "Image" selected (lime underline), "Video" inactive |
| `idle` — output toggle video | Toggle shows "Video" selected (lime underline), "Image" inactive |
| `flushing` | Render button label: "Saving…", `disabled`, `opacity-50` |
| `chrome-download` | Render button hidden; Chrome-download gate visible with progress bar |
| `rendering` (video) | Render button hidden; frame progress row visible with spinner + counter |
| `done` (video) | `<video>` preview visible + Download / Open folder / Copy caption actions |
| `failed` | Red error text + "Retry render" button (same as Phase 5) |

Hover: button shadow shrinks (inherited from Workspace button pattern).
Active: `translate-x-[2px] translate-y-[2px]`, shadow none.
Focus: `outline-2 outline-offset-2 outline-[var(--workspace-lime)]` on all interactive elements.

## Layout Contract

Phase 6 adds to the existing Editor layout — no layout restructuring.

```
Editor (two-column: canvas left, controls right)
└── Right column
    ├── [existing] BrandPicker
    ├── [existing] SlotPanel
    ├── [NEW] OutputToggle  ← image | video two-segment control
    │     Below the SlotPanel, above the RenderPanel
    └── RenderPanel (extended)
          ├── [idle/image] "Render images" button  ← Phase 5 unchanged
          ├── [idle/video] "Render video" button
          ├── [flushing]   "Saving…" button
          ├── [chrome-download] Chrome-download gate
          │     ├── Heading: "One-time setup"
          │     ├── Body: "Downloading Chrome renderer…"
          │     ├── Progress bar (lime fill, border-[var(--workspace-border)])
          │     └── Note: "Render will start automatically."
          ├── [rendering/video] Frame progress row
          │     ├── Spinner (same 4-sided CSS spinner as Phase 5)
          │     └── "NNN / 240 frames" (Geist Mono 12px)
          ├── [done/image] <img> preview + actions  ← Phase 5 unchanged
          └── [done/video] <video> preview + actions
                ├── <video muted controls> served from /output/<id>/<format>.mp4
                └── Actions: Copy caption | Download video | Open folder
```

OutputToggle dimensions: same `max-w-[420px]` width-cap as FormatSwitcher. Two columns (`grid-cols-2`). Segment min-height: 40px (touch-safe). Sits in a `rounded-[8px] border border-[var(--workspace-border)] bg-[var(--workspace-surface)] p-1` container — identical to FormatSwitcher.

Progress bar (Chrome download): full width, height 8px, `rounded-full`, bg `var(--workspace-border)` track, lime fill. Uses a CSS `width` property driven by the integer percentage value from `onBrowserDownload`.

## Accessibility Contract

| Requirement | Implementation |
|-------------|---------------|
| Output toggle keyboard | `role="tablist"` / `role="tab"` / `aria-selected` — same pattern as FormatSwitcher |
| Chrome-download gate | `aria-live="polite"` on the panel already present; no additional role needed |
| Progress bar | `role="progressbar"` `aria-valuenow={pct}` `aria-valuemin={0}` `aria-valuemax={100}` `aria-label="Chrome download progress"` |
| Frame counter | `aria-live="polite"` on the counter span OR inherited from the panel's existing `aria-live="polite"` |
| Video preview | `<video>` with `aria-label="Rendered video preview"` + `muted` + `controls` |
| All interactive min target | `min-h-[44px]` on buttons/anchors (carried from Phase 5) |
| Focus ring | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[var(--workspace-lime)]` |
