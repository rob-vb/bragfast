onBrowserDownload pattern (RESEARCH.md Q3 — CRITICAL pitfall avoidance):
Only set job.phase = "chrome-download" when alreadyAvailable === false.
When alreadyAvailable === true, return early without mutating job.phase.
This prevents the Workspace from flashing the Chrome download gate on cached renders.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → POST /api/local/render/video | Untrusted body: draftId, format. Both must be validated before use. |
| HTTP client → GET /api/local/render/video/:id/status | req.params.id used as Map key and in path construction — path traversal risk. |
| CLI process → @remotion/renderer (headless Chrome) | Remotion starts a subprocess; inputProps must be JSON-serializable (Pitfall 4 in RESEARCH.md). |
| CLI server → /media static route | Serves files from ~/.brag/media; headless Chrome fetches via absolute localhost URL. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-CLI | Spoofing | POST /api/local/render/video origin | mitigate | Inherits originLockMiddleware (hostGuard + CORS) already applied in buildApp — no per-route change needed |
| T-06-02-CLI | Tampering | req.params.id in status route | mitigate | isUnsafeOutputId(id) guard rejects ".." and "/" before Map lookup (mirrors image status route pattern) |
| T-06-03-CLI | Tampering | body.draftId used as filesystem segment in outputDir/<draftId>/ | mitigate | draftId is the job key from the backend; video-render-resolver writes to path.join(outputDir, draftId, format+".mp4") — same pattern as image resolver which doesn't path-traverse because draftId comes from the authenticated backend response, not raw user input. isUnsafeOutputId check on the id at the status endpoint catches any attempt to poll with a traversal id. |
| T-06-04-CLI | Information Disclosure | /media static route serving ~/.brag/media | accept | Existing Phase 4 route; localhost-only; originLockMiddleware already applied |
| T-06-05-CLI | Denial of Service | Multiple concurrent video renders (each ~70s, ~200-400MB RAM) | accept | Local tool, single developer; no concurrent render limit needed for MVP |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this plan |
</threat_model>
