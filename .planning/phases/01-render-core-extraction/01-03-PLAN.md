<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| packages/render-core/src/fonts.ts → ~/.brag/fonts/ | Google Font bytes fetched from network and written to user's home directory disk cache |
| Caller-provided font family name → ~/.brag/fonts/ filename | Font family name used to construct cache file path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | ~/.brag/fonts/ disk cache — path construction | mitigate | Font cache filename derived from `family.replace(/\s+/g, "_")` + weight — no path separators in family names; family names come from the template config (controlled by the user), not from network input. Validate that family name contains no "/" or ".." before writing. |
| T-03-02 | Elevation of Privilege | ~/.brag/fonts/ — arbitrary font bytes to disk | accept | Font bytes from Google Fonts CDN; CDN is attacker-influenceable only if fonts.google.com is compromised; realistic severity LOW; font bytes are loaded into Satori for rendering only, not executed |
| T-03-03 | Information Disclosure | Google Fonts HTTP request | accept | Request reveals font family name to Google; no user PII sent; standard web behavior |
| T-03-04 | Denial of Service | ~/.brag/fonts/ fill-up | accept | Font TTF files are ~200KB each; cache only grows with explicit render calls; not a realistic attack surface for a local CLI tool |
| T-03-SC | Tampering | npm/pip installs | accept | No new package installs in this plan — source files only |
</threat_model>
