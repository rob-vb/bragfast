    resolveAndRender(draftId: string, apiKey: string, backendBase: string, outputDir: string, port: number, stdout: NodeJS.WriteStream): Promise<RenderJob>
    — Implementation steps (per D-02, the CLI renders the persisted Draft):
    1. Fetch Draft via GET ${backendBase}/api/v1/drafts/${encodeURIComponent(draftId)} with Authorization: Bearer ${apiKey}. Throw with message "Draft not found: ${draftId}" if 404.
    2. Fetch brand via GET ${backendBase}/api/v1/brands if draft.config.brandId is set; find matching brand from the array. Graceful fallback: if no brand or no brandId, use fallback Brand with colors from draft.config.colors or template defaults.
    3. Resolve logo: if brand has logo_url, fetch it with node fetch → Buffer → base64 data URI. Assign to logoBase64. Catch errors → logoBase64 = "".
    4. Build ObjectDataMap per format: replicate the buildDraftObjectData logic from packages/workspace/src/lib/buildDraftObjectData.ts. This file imports @bragfast/render-core/browser — do NOT import it in the CLI resolver; instead, write a local pure function buildObjectDataForCLI(templateConfig, objectContent, format) that produces ObjectDataMap using the same logic. Import CanvasTemplateConfig and ObjectDataMap from @bragfast/render-core (node, not /browser).
    5. Resolve local media refs: objectContent entries with image_url starting with "/media/" must be resolved to their disk path: path.join(getBragHome(), "media", basename(image_url)). Read the file and convert to base64 data URI ("data:image/jpeg;base64,..."). If the file does not exist, log "Missing media: ${absPath}" to stdout and set imageBase64 to "" (per D-12 partial failure — render continues, format will likely fail at render-core with a clear error).
    6. Resolve template: read draft.config.templateId. Call resolveTemplate from @bragfast/render-core or use the built-in templates map (import BUILT_IN_TEMPLATES from render-core or from the same source as Phase 4 used). If templateId starts with "tmpl_", it is a custom template — fetch from backend. Built-ins are available from packages/render-core/src/canvas-defaults.ts (or re-export in index.ts — check first).
    7. Assemble LocalRenderRequest: formats array with entries for "landscape", "square", "portrait" — each with a single LocalRenderSlide (one slide per format). srcMap: collect any remote image URLs (template static src fields beginning with http) and pre-fetch them via node fetch → base64 using the same node fetch approach. Assign to srcMap keyed by original URL.
    8. Call renderImage(req) from @bragfast/render-core. Per D-12, render all formats even if individual ones may fail. Because renderImage renders all formats in one call, wrap in try/catch per format AFTER the call using the returned result: if a format key is missing from result.formats, mark it failed. If renderImage itself throws, mark all formats failed.
    9. Write outputs: for each format in result.formats, write result.formats[format].slides[0] (Buffer) to path.join(outputDir, draftId, "${format}.jpg") using fs.mkdir({ recursive: true }) then fs.writeFile. Construct the URL as "/output/${draftId}/${format}.jpg". Per-format write errors should mark that format failed (not abort all).
    10. Log per-format progress to stdout as each format completes, e.g.: "  [brag] landscape rendered\n" (per D-03).
    11. Return a RenderJob with formats record populated with done/failed states.

    NOTE on backendBase: the backend base URL is available on the CLI server as the BRAG_API_BASE env var (set by Phase 2/3 bootstrap). In server.ts, read process.env.BRAG_API_BASE ?? "https://api.brag.fast" and pass it into resolveAndRender.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Workspace SPA → CLI server | All new endpoints receive browser fetch from localhost; origin-lock already enforces same-port; body params are attacker-controlled strings |
| CLI server → disk | id/draftId params from the request body are used to construct file paths; unsanitized values enable path traversal |
| CLI server → OS process | Open-folder endpoint would enable command injection if id is interpolated into a shell command; must use open() arg passing only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | GET /api/local/render/:id/status — :id param used in Map lookup | mitigate | Validate id: reject strings containing ".." or "/" before lookup; 400 response |
| T-05-02 | Tampering | GET /output static route — serves any file under outputDir | accept | express.static with a fixed root dir does not traverse above the root; no dynamic path construction; safe |
| T-05-03 | Elevation of Privilege | POST /api/local/reveal — id used to build path passed to OS open | mitigate | Validate id (no ".." or "/"); path.resolve + startsWith(path.resolve(outputDir)) guard; use open() not shell exec |
| T-05-04 | Information Disclosure | POST /api/local/render — reveals draft/brand data from backend | accept | Endpoint is behind origin-lock; only the local Workspace SPA can call it; no new trust boundary opened |
| T-05-05 | Denial of Service | In-memory renderJobs Map — unlimited growth if render is called repeatedly | accept | Single-user local CLI; job map bounded by session lifetime; acceptable for v1 |
| T-05-SC | Tampering | No new npm packages in this plan | accept | No package-manager installs; existing packages only |
</threat_model>
