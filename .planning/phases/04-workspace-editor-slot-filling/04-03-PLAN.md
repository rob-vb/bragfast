  <name>Task 2: Implement debounced full-config auto-save hook</name>
  <files>
    packages/workspace/src/hooks/useAutoSave.ts,
    packages/workspace/src/__tests__/useAutoSave.test.tsx
  </files>
  <read_first>
    - packages/workspace/src/api.ts — createDraft and patchDraft helpers from Task 1
    - src/app/api/v1/drafts/[id]/route.ts — confirms PATCH shallow merge
    - .planning/phases/04-workspace-editor-slot-filling/04-RESEARCH.md — Pattern 3 and Pitfall 3
    - .planning/phases/04-workspace-editor-slot-filling/04-UI-SPEC.md — Interaction States / Auto-save copy
  </read_first>
  <behavior>
    - when config is null, no create or patch call fires
    - when draftId is null and a dirty full config appears, one create call fires after 900ms and returns a draft id
    - when draftId exists, one patch call fires after 900ms with the full config object
    - repeated edits before 900ms collapse to a single save
    - failure leaves status as `Save failed - retrying on next edit` or an equivalent enum consumed by that UI copy
  </behavior>
  <action>
    Implement `useAutoSave` around refs and `setTimeout` with a 900ms delay. The hook should expose save status (`idle`/`unsaved`/`saving`/`saved`/`error`) plus the current saved draft id if it created one.

    The caller owns deciding what counts as first content edit; the hook must not save `null` config. Once called with a non-null dirty config, POST if no draft id exists and PATCH otherwise. PATCH must receive the full DraftConfig argument.
  </action>
  <verify>
    <automated>npx vitest run --config packages/workspace/vitest.config.ts packages/workspace/src/__tests__/useAutoSave.test.tsx</automated>
  </verify>
  <acceptance_criteria>
    - useAutoSave uses a 900ms debounce or another value between 800ms and 1000ms
    - tests prove template browsing/null config does not create a draft
    - tests prove PATCH receives a full config containing objectContent and caption
    - tests prove rapid edits result in one save call
  </acceptance_criteria>
</task>
