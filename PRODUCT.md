# Product

## Register

brand

## Users

Solopreneurs and indie hackers who already believe building in public works. They ship code weekly, run a SaaS or side project, and have a GitHub habit. The problem isn't motivation — it's the context switch. They open the post composer after merging, blank out, and close the tab. The ICP wedge is GitHub users. Deprioritized: DevRel teams, AI agent builders, non-technical creators, people who aren't already shipping.

## Product Purpose

brag.fast turns the work you already do (merging PRs, hitting milestones) into approved social posts, automatically. GitHub App watches your repos; each merge triggers a draft (image, video, or thread); one tap sends it. The unit is the post approval event, not the content format. Positioning: "Build in public, automated." The builder stays in the editor. The audience gets fed.

## Brand Personality

Scrappy, effortless, irreverent.

Voice: 80% casual, 75% playful, 80% terse. Short punchy sentences. No corporate speak. Core metaphor is the breakfast diner — templates are recipes, rendering is cooking, admin is the kitchen. CTAs are low-friction; "no credit card required" repeats throughout.

Vocabulary in: ship, cook, plate, serve, recipe, kitchen, credits, hands-free, zero design.
Vocabulary out: enterprise, workflow, asset management, streamline, leverage, synergy, no em dashes.

## Anti-references

- Duolingo-style guilt streaks — wrong tone, wrong emotional model.
- Generic SaaS dashboards — navy gradients, hero metrics, identical card grids.
- "Creative suite" or DAM framing — this is not an image generator with integrations bolted on.
- Native scheduling features — Buffer/Postiz own that; brag.fast hands off.
- MCP / agent / API language on public surfaces — developer infrastructure, demoted to footer.
- Glassmorphism, gradient text, side-stripe borders — see impeccable shared bans.

## Design Principles

1. **Effortlessness is the product.** Every surface should feel like less work. Remove friction before adding features. If a screen requires explanation, simplify it.
2. **Show, don't tell.** Founder dogfooding (@the_robvb) and live proof beats copy claims. Credibility through demonstration, not assertion.
3. **Builders, not marketers.** Language, UX, and design speak to someone mid-sprint. Sprint rhythms over content calendars. Features over metrics.
4. **Honest about early-stage.** v0.X scrappiness is alignment with the audience, not apology. Frame it as "you watch it grow, you shape it, you get early-adopter pricing."
5. **Irreverence with precision.** The NES-retro diner aesthetic is a committed choice, not decoration. Every pixel is intentional. Playfulness does not mean sloppy.

## Accessibility & Inclusion

WCAG 2.1 AA. Minimum contrast ratios enforced. Keyboard-navigable interactive elements. Screen-reader-friendly landmarks and labels. Minimum touch targets 44×44px on mobile. Reduced motion: respect `prefers-reduced-motion` for all animations. Press Start 2P minimum 10px for readable text.
